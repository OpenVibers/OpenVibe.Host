# No 502s during a deploy (2026-10-31)

On 2026-10-31 the owner opened openvibe.codes/auth/login in the same second a Codes deploy restarted the service, and
got Cloudflare's "Bad gateway". The disk was fine (80%). The cause was the restart: Codes closed its port, nginx could
not connect, and nginx answered 502. On that day 45 of the 50 services restarted this way. Every deploy, and so every
Shared pin round, gave each site a window of 502s lasting from 1 to 7 seconds.

There are two fixes, and both apply to every site.

## 1. The listener outlives the restart: socket activation

The service's server listens on the descriptor systemd hands it when it is socket-activated:

```js
const socketActivated = process.env.LISTEN_FDS === '1' && Number(process.env.LISTEN_PID) === process.pid;
const server = app.listen(...(socketActivated ? [{ fd: 3 }] : [config.port, config.host]), () => { … });
```

Without a socket unit, the service listens on its port as before, so the code can be deployed first.

Then, on the host, `scripts/ov-socketize.sh <service>` (installed as `/usr/local/sbin/ov-socketize`) switches the
service over:
1. It writes `<name>.socket` on `127.0.0.1:<port>` (loopback only; with no `PartOf=`, the socket outlives every
   restart) and the drop-in `<unit>.d/socket.conf` (`Requires`/`After` on the socket, plus `NonBlocking=true`).
2. It stops the service, starts the socket, then starts the service. It checks that systemd (pid 1) holds the port,
   and records `socketUnit` in host.json, after backing host.json up to /root.
3. **The proof:** it sends 40 requests while it restarts the service, and none may be refused. Codes passed on
   2026-10-31 with 0 of 40 refused.

`ovhost validate` warns about any service that has a port but no socket unit.

## 2. If a site is down anyway: our page, not Cloudflare's

`deploy/nginx/snippets/ov-down.conf` turns nginx's own 502 and 504 (the upstream refused the connection or timed
out) into a **503** with `Retry-After: 5`. It serves `deploy/www/openvibe-down/down.html` (installed in
`/var/www/openvibe-down/`): "Back in a moment", with the site's name. The page reloads itself as soon as the site
answers.

- **Why 503:** Cloudflare passes an origin's 503 page through, but replaces an origin's 502 or 504 with its own
  branded error page.
- **What it does not catch:** responses the app sends itself pass through unchanged (`proxy_intercept_errors` stays
  off).
- **No outside assets:** the page loads nothing from anywhere, because the site it stands in for is down.

On the host the snippet is included from `/etc/nginx/snippets/security-txt.conf`, which every proxying vhost already
includes. The two API vhosts, `bench-render` and `s3.openvibe.media`, do not include it on purpose: an HTML page would
be wrong for their clients.
