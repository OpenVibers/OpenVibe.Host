# Compatibility register (roadmap Wave 22)

The Wave 22 exit rule is: "every compatibility shim is gone or has a dated, owned removal plan". This page
lists every compatibility shim, legacy route, dual write or mirror, rollback flag and legacy secret found
in the estate on 2026-09-23. For each one it gives the owner, the removal condition, a target date and the
rollback lever that the shim keeps available until it is removed.

**How this was built.** Source was read in every repository under `~/OpenVibers` and in Live at
`~/orca/workspaces/OpenVibe.Live/seadragon` (`ae07553`), excluding `node_modules`. The search terms were
`_AUTHORITY`, `_LEGACY`, `legacy`, `deprecated`, `compat`, `fallback`, `shim`, `INTERNAL_API_KEY`,
`X-Internal-Key` and `frozen`. Paths are relative to each repository, and `file:N` is a line number.
Production facts come from the operator notes of 2026-09-23.

**Conditions and dates.**
- *documented*: the condition is quoted from the cited doc or ADR.
- *proposed*: the condition was set by this register. No repo recorded one before.
- Every date is a target. A target moves only when this page is edited, and the edit gives the reason.
- Where a condition needs telemetry that does not exist yet, the entry says so.

**Owner.** The owner is the service that must make the change. In an entry, "owner" alone means that
service's maintainers, which today means the OpenVibe operator (`OpenVibers`).

Contracts has no deprecated contracts and no aliases (`OpenVibe.Contracts/compatibility/deprecations.json`,
`compatibility/aliases.json` are both empty).

## The shared internal key (`INTERNAL_API_KEY` / `X-Internal-Key`)

Network `docs/retirement.md` gives the procedure:
- Telemetry in `principal_usage` has run since 2026-09-23. Guarded routes are counted as `auth='internal-key'`, other internal routes as `auth='internal-key-route'`.
- Move a caller to a service token, wait until the route shows no legacy-key calls for **14 days**, remove the key path for that route, and finally delete `INTERNAL_API_KEY` from every env file.
- ADR-003: "the key is retired per route once legacy use reaches zero".
- First observation: `GET /internal/url-registry/resolved`, from Live's registry refresh (2026-09-23 04:50 UTC).
- **No HTTP route lists `principal_usage`.** Read it with the SQL in `docs/retirement.md`.

The dates below assume each caller moves by **2026-10-09**. The key paths then go on **2026-10-23**, and the variable goes from every env file on **2026-11-06**. Where a route has no counter, the entry says so.

## Kept by design (not shims)

These match the search terms but are permanent. They are listed so the next review does not re-open them.

- **Network `identity_legacy_map`** and `POST /internal/identity/legacy-map`: ADR-001 keeps legacy ids alongside subject ids permanently (Network `server/identity/subjects.js:25-35`). The *key* on that route is C-50.
- **Network legacy public-key shape**: `public_key` PEM is served beside the spec shape (`server/index.js:371-386`). Billing, Blog, Chat, Codes, Community, Coupons, AI, Host, Media and Events read `public_key`. Removing it would be a breaking change for all of them.
- **Network `my.openvibe.network`**: 301 to the apex (`server/index.js:571`).
- **Network status poll `basis: 'ready-legacy'`** for readiness bodies not built on `openvibe-shared/ready` (`server/registry/ecosystem.js:37-45`). AI, Billing, Chat, Search, Sources, Tips and OpenRe use their own handlers.
- **Analytics `ip`/`user_id`/`city` columns** kept and always NULL: Network `server/analytics/schema.js:1-14`, Tools `apps/_shared/analytics/schema.js:3-6`.
- **Billing `legacy_order_id`/`legacy_live_txn`/`legacy_live_id`**: import provenance (`server/db.js:120,142,162`). Tips `legacy_source` and VIP `vip_migration_maps` are the same kind of provenance.
- **Tools registry fallback list** until Network answers (`registry/services.js:16-24`), and `isLegacyHost` for the old paste/login hosts (`index.js:104-105`).
- **Games `EDITOR_KEY`**: "Fallback admin secret for the map editor (until openvibe.network SSO)" (`apps/server/src/config.ts:82-83`). This one *is* a legacy secret, with no removal date. *Proposed*: SSO staff check for the editor by 2026-11-06, owner Games.
